# 地图数据包说明

应用的全部内置地图数据以 **DMAP 加密容器**（`.dmap`）随仓分发，位于
`apps/web/public/assets/<代号>/`。每张地图拆为一组独立容器：索引容器先到先渲染 UI，
3D 分块、导航与 2D 沙盘容器按需拉取。克隆仓库即可使用，无需任何额外下载或生成步骤。

- **spacecenter 与其余地图同一标准随仓分发**（完整楼层、POI、2D 与区域数据），没有
  单独的功能限制或降级。

## 2. 容器内结构

每张地图的数据拆为「索引容器 + 分块容器 + 导航容器」三组独立 DMAP 容器：

```
assets/<code>/index.dmap          索引容器（dmap-map-manifest/3）
  manifest.json                   单图清单：map/floors/counts/entries/chunks 分块索引
  maps/<code>/scene.json          楼层值、场景包围盒、楼层触发体
  maps/<code>/poi.json            POI 全量（含坐标、楼层、图标、显隐标记）
  maps/<code>/map2d.json          每楼层 2D 标定（世界系范围 ↔ 像素）
  configs/                        类型 / 物品 / 区域 / 地图配置表（清洗后）
  icons/                          图标索引与 PNG（hash 文件名）
  minimap/                        2D 底图索引与 PNG（hash 文件名）

assets/<code>/chunks/c_<x>_<y>.dmap   分块容器：单条目 chunk.glb（实例化 GLB 几何）
assets/<code>/nav.dmap                导航容器：单条目 navmesh.json（寻路网格）
assets/<code>/sandbox2d.dmap          2D 沙盘容器（dmap-sandbox2d-manifest/1，5 图可选）
```

**2D 沙盘容器**（全页 2D 沙盘视图的数据源，与 3D 索引容器完全独立）：

```
sandbox2d/manifest.json    沙盘清单：counts + meta（tileTemplate/siteFloors/floorMap/difficultyOptions）
sandbox2d/data.json        清洗后数据：regions（区域名，en/繁/简三字段）
                           points（点位：坐标/楼层/难度/名称语言字段族/媒体引用）
                           legend（57 类图例：分组/计数/图标/色块）
                           overlays（楼层叠加：锚点/宽高）
                           meta.linkAffine（站点像素 ↔ 3D 世界系仿射，区域级近似定位）
tiles/**                   瓦片金字塔（512px WebP，纯网格坐标路径；z1–z3 原生、z4–6 上采样；
                           az3 为整层换图模板 tiles/{floor}/{z}/{x}/{y}.webp）
overlays/<sha16>.webp      楼层叠加层（四图模式；az3 无叠加）
icons/index.json + *.png   图例图标（≤128px PNG，业务键索引）
media/index.json + *.webp  POI 物品图/用户截图（≤832px WebP q75；数据无引用或上游对象已失效以 null 占位）
```

2D 沙盘坐标为独立的站点像素口径（4096²、POI 与区域标注两套轴约定互为转置），与
3D 侧烘焙图的标定口径不互通；两视图间的定位经 `meta.linkAffine` 做区域级近似换算。

清单 `chunks[]` 是分块索引：容器文件名、字节规模（原始 GLB / 容器内载荷 / 密封容器）、
实例数与 AABB，供引擎按需加载、取景与进度聚合。加密与字节级布局（magic、AES-256-GCM、
dmapc 索引、密钥派生、两段式加载）见
[packages/dmap/FORMAT.md](../packages/dmap/FORMAT.md)。保护等级的诚实口径：
容器防篡改真实有效；密钥材料随客户端分发，防提取为威慑级设计。

## 3. 数据清洗策略

容器内 JSON 为管线产出的稳定形态，遵循五条清洗规则：

1. **字段最小化**：各 JSON 只保留应用运行时消费的字段（例如地图配置表仅保留
   `MapId` 与 `DefaultBornPos`，版本号数组与未消费字段不随包分发）。
2. **语言键中性化**：数据内的多语言键值统一替换为中性键
   （POI 标注 `poi.<id>.location` / `poi.<id>.description`，区域 `region.<Id>`）。
   界面展示直接使用数据包内的明文文案，键值不参与翻译查找。
3. **资产 hash 命名**：图标与 2D 底图文件名改为内容 SHA-256 前 16 位 hash；
   `icons/index.json`、`minimap/index.json` 保留业务键用于查找。
4. **场景资产中性化**：3D 分块 GLB 的节点名与网格名一律为中性序号
   （`n0..nN` / `geo0..geoM`），节点不携带 extras——上游摆放路径等调试信息不入包，
   引擎仅按几何与实例属性消费。
5. **陈旧数据防线**（全部基于内容实测，见 §3.1）。

**保留业务键的口径**：`icons/index.json`、`minimap/index.json` 的查找键与 2D 楼层名
（拼音代码，如 `db` / `cgxg` / `_-1f` 后缀）是数据包内部的查找键，用于图标检索与
楼层匹配，应用与文档均以此口径消费；它们不指向任何外部工具或来源。

### 3.1 陈旧数据防线

源摆放表与配置表存在少量陈旧行，管线在转换时按内容实测逐图校验：

- **离群 chunk 剔除**：与其他分块包围盒均相距超过 512m、且不与 2D 概览标定区相交的
  分块判为陈旧摆放行（如位于世界原点的零星构件），不入包——零号大坝剔除 1 块
  （2 实例）、长弓溪谷剔除 1 块（47 实例），其余 4 图无剔除；
- **场景包围盒校验**：源场景包围盒中心若落在内容空洞上（距最近分块超过 350m，
  按中心取景会导致流式加载半径内无分块），改用剔除离群后的分块内容并集；
  长弓溪谷适用（其内容实际分布于概览标定区一带）；
- **出生点校验**：`DefaultBornPos` 必须落在 2D 概览标定区内，越界的陈旧出生点
  替换为概览区中心（Y 取区内摆放高度中位数）——长弓溪谷与航天基地的出生点为
  源数据陈旧行，已按本规则替换。

应用侧消费端（`apps/web/src/data/`）与上述键位一一对应，并由随仓测试
（`apps/web/src/data/loadMap.test.ts` 的 6 图真实容器回归）逐图校验；
2D 沙盘容器的同口径回归为 `apps/web/src/sandbox2d/loadSandbox2d.test.ts`（5 图）。

## 4. 加载行为与失败状态

- **两段式加载**：切图只拉索引容器（几 MB，进度 0 → UI 就绪）——POI/2D/配置数据
  随索引即可渲染；3D 分块容器由引擎按相机需要并行拉取（并发池 6、失败重试 1 次），
  总进度按「已载实例 / 总实例」跨流聚合；
- **切换缓存**：同一数据包的索引下载与校验结果按 MapId 缓存，重复切换不重复下载；
  分块容器常驻缓存直至切图释放；
- **失败三态**：容器缺失或网络不可达 → `unavailable`（切换器提示「数据包准备中」，
  支持重试）；完整性校验或清单不合法 → `corrupt`；其余 → `unknown`。
  状态栏展示归类文案，完整原因进控制台。

## 5. 维护约定

- 容器由私有资产管线生成后整体入仓；应用侧只读消费，不在仓库内重建。
- 更换密钥材料（`apps/web/src/engine/dmapKey.ts`）必须同步重建全部 `.dmap`，
  手工修改会导致完整性校验失败。
- 新增或更新容器后，请同步更新本文件的规模表与
  `apps/web/src/data/loadMap.test.ts` 的真实容器回归。
