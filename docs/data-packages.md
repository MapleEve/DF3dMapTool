# 地图数据包说明

应用的全部内置地图数据以 **DMAP 加密容器**（`.dmap`）随仓分发，位于
`apps/web/public/assets/<代号>.dmap`。克隆仓库即可使用，无需任何额外下载或生成步骤。

- **导航数据**：除场景容器外，另有 `<代号>.nav.dmap` 加密导航容器随仓分发

  单独的功能限制或降级。

## 2. 容器内结构

每个 `.dmap` 容器承载一张地图的全部数据，并内嵌全部 6 张图的索引摘要：

```
manifest.json                  dmap-map-manifest/2：maps[] 索引（6 条）
  ├─ 索引摘要条目：mapId / code / floors / containers / counts
  └─ 本容器承载的地图条目额外携带：
       entries       scene / poi / map2d / configs[4] / icons / minimaps 的包内路径
       chunkBounds   3D 分块包围盒（引擎按需流式加载与取景）
maps/<code>/scene.json         楼层值、场景包围盒、楼层触发体
maps/<code>/poi.json           POI 全量（含坐标、楼层、图标、显隐标记）
maps/<code>/map2d.json         每楼层 2D 标定（世界系范围 ↔ 像素）
chunks/b*.glb                  3D 分块几何（实例化摆放）
configs/                       类型 / 物品 / 区域 / 地图配置表（清洗后）
icons/index.json               图标索引（业务键 → hash 文件路径 + 尺寸）
minimap/index.json             2D 底图索引（业务键 → hash 文件路径 + 尺寸）
```

加密与字节级布局（magic、AES-256-GCM、dmapc 索引、密钥派生）见
[packages/dmap/FORMAT.md](../packages/dmap/FORMAT.md)。保护等级的诚实口径：
容器防篡改真实有效；密钥材料随客户端分发，防提取为威慑级设计。

## 3. 数据清洗策略

容器内 JSON 为管线产出的稳定形态，遵循五条清洗规则：

1. **字段最小化**：各 JSON 只保留应用运行时消费的字段（例如地图配置表仅保留
   `MapId` 与 `DefaultBornPos`，版本号数组与未消费字段不随包分发）。
2. **语言键中性化**：数据内的多语言键值统一替换为中性键
   （POI 标注 `poi.<id>.location` / `poi.<id>.description`，区域 `region.<Id>`）。
   界面展示直接使用数据包内的明文文案，键值不参与翻译查找。
3. **资产 hash 命名**：图标与 2D 底图文件名改为内容 SHA-256 前 16 位 hash；
   `icons/index.json`、`minimap/index.json` 保留业务键用于查找。
4. **场景资产中性化**：3D 分块 GLB 的节点名与网格名一律为中性序号
   （`n0..nN` / `geo0..geoM`），节点不携带 extras——源侧摆放路径等调试信息不入包，
   引擎仅按几何与实例属性消费。
5. **陈旧数据防线**（全部基于内容实测，见 §3.1）。

**保留业务键的口径**：`icons/index.json`、`minimap/index.json` 的查找键与 2D 楼层名
（拼音代码，如 `db` / `cgxg` / `_-1f` 后缀）是数据包内部的查找键，用于图标检索与
楼层匹配，应用与文档均以此口径消费；它们不指向任何外部工具或来源。

### 3.1 陈旧数据防线

源摆放表与配置表存在少量陈旧行，管线在转换时按内容实测逐图校验：

- **离群 chunk 剔除**：与其他分块包围盒均相距超过 512m、且不与 2D 概览标定区相交的
  分块判为陈旧摆放行（如位于世界原点的零星构件），不入包——零号大坝剔除 1 块
  （2 实例）、长弓溪谷剔除 1 块（47 实例），其余 4 图无剔除；
- **场景包围盒校验**：源场景包围盒中心若落在内容空洞上（距最近分块超过 350m，
  按中心取景会导致流式加载半径内无分块），改用剔除离群后的分块内容并集；
  长弓溪谷适用（其内容实际分布于概览标定区一带）；
- **出生点校验**：`DefaultBornPos` 必须落在 2D 概览标定区内，越界的陈旧出生点
  替换为概览区中心（Y 取区内摆放高度中位数）——长弓溪谷与航天基地的出生点为
  源数据陈旧行，已按本规则替换。

应用侧消费端（`apps/web/src/data/`）与上述键位一一对应，并由随仓测试
（`apps/web/src/data/loadMap.test.ts` 的 6 图真实容器回归）逐图校验。

## 4. 加载行为与失败状态

- **切换缓存**：同一容器的下载与校验结果按 MapId 缓存，重复切换不重复下载；
- **进度**：容器下载约占 70% 进度权重，其余由 3D 分块流式加载推进；
- **失败三态**：容器缺失或网络不可达 → `unavailable`（切换器提示「数据包准备中」，
  支持重试）；完整性校验或清单不合法 → `corrupt`；其余 → `unknown`。
  状态栏展示归类文案，完整原因进控制台。

## 5. 维护约定

- 容器由私有资产管线生成后整体入仓；应用侧只读消费，不在仓库内重建。
- 更换密钥材料（`apps/web/src/engine/dmapKey.ts`）必须同步重建全部 `.dmap`，
  手工修改会导致完整性校验失败。
- 新增或更新容器后，请同步更新本文件的规模表与
  `apps/web/src/data/loadMap.test.ts` 的真实容器回归。
